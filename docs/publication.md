# Publication and release operations

The repository is prepared for public access, but publication requires a maintainer review. The bundled Wizards-derived playmats and other third-party material have not been cleared for redistribution: see [third-party notices](../THIRD_PARTY_NOTICES.md). Review the application and all third-party content under the applicable terms and obtain any necessary permissions before making the repository or builds public. Attribution alone is not permission.

## Before publication

1. Review `git status --short` and select the intended source, documentation, tests, workflows and assets explicitly; do not stage generated output or local configuration. Review the complete Git history and the files to be committed for credentials, private data, and third-party material. Revoke exposed credentials before publication. Removing a file from the current tree does not remove it from history; coordinate any required history rewrite separately.
2. Review Firebase Security Rules, authorization, quotas, billing and API key restrictions. Firebase Web configuration is public in the shipped app; server credentials and `CLOUDFLARE_TURN_API_TOKEN` must never be included. Verify the production backend separately, including Functions and relay configuration.
3. In GitHub repository settings, enable Actions and private vulnerability reporting. Protect `main`: require pull requests and the `Application checks` and `Functions build` checks, block force pushes and restrict bypass permissions. Ensure GitHub Actions can create releases, and permit its `GITHUB_TOKEN` to write repository contents for the publish job.
4. Under **Settings → Secrets and variables → Actions → Variables**, set `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_DATABASE_URL`, `VITE_FIREBASE_PROJECT_ID` and `VITE_FIREBASE_APP_ID` to the production Firebase Web app configuration. Optionally set `VITE_FIREBASE_MESSAGING_SENDER_ID`, `VITE_FIREBASE_STORAGE_BUCKET`, and `VITE_TURN_WORKER_URL` to the public HTTPS Worker URL. These values are compiled into every executable. Do not enter service-account credentials or TURN secrets.
5. Only after the rights and security reviews are resolved, set the repository variable `PUBLICATION_APPROVED` to `true`. The release job fails closed while it is missing or different. Configuration of GitHub, Firebase and publication itself require maintainer access and are not performed by the workflow.

## Automated releases

Pull requests run application and Functions checks without production credentials. A push to `main` runs the same checks, followed by Windows x64 packaging. Release runs share a queue; GitHub permits up to 100 pending runs and cancels further runs if that queue fills. A failed check, missing configuration or failed build prevents release publication.

The release uses the version in `package.json` when it is newer than all stable `vMAJOR.MINOR.PATCH` tags; otherwise it increments the highest stable tag's patch version. For example, a base of `0.0.3` with no later stable tag produces `v0.0.3`. To move to a new major/minor line, update the base version in a reviewed change. The calculated version changes only the temporary build workspace; there is no automated commit to `main`. A tag points to the exact pushed commit, and the ZIP filename and embedded package version use the computed version.

The publication job creates or resumes a draft release, uploads the ZIP and `SHA256SUMS.txt`, downloads the assets back and verifies the checksum before publishing. Re-running a completed release for the same commit is a no-op; an incomplete draft is resumed. If a partial upload or release failure occurs, inspect the draft and rerun the workflow. If a tag exists without a release, it remains reserved and the next run chooses the next version. Do not manually retarget release tags.

The release is unsigned and does not auto-update. Extract the complete ZIP and launch `meu-magic.exe` from the extracted folder. The ZIP distributes the Electron runtime directly, without the NSIS self-extracting launcher used through v0.0.6. Included notices are available in `resources/legal` without launching the application. Public release access exposes the configured Firebase Web values, as intended.

Before upload, the Windows packaging job updates Microsoft Defender signatures and scans the finished ZIP with `scripts/scan-windows-release.ps1`. A detection, unavailable scanner, failed signature update or scan error prevents publication. The custom scan uses `-DisableRemediation` so a successful malware removal cannot be mistaken for a clean scan; archives are inspected and exclusions are ignored. This does not change system protection settings. A clean scan reflects that engine and signature version at that time and cannot guarantee future cloud verdicts. See the [v0.0.6 investigation](windows-defender-0.0.6.md).

## Review record: 2026-10-26

- Gitleaks 8.30.1 scanned all locally available Git refs and a copy of the tracked and non-ignored candidate files. Both scans reported one generic-key alert on `tests/fixtures/precon-hashes.json:11`; it is a 64-character SHA-256 deck fixture, not a credential. Ignored local files were intentionally excluded from the candidate-file scan and must stay out of the repository. This automated scan is not a guarantee that no private material remains.
- The source and terms for Wizards-derived playmats, MTGJSON and Scryfall are documented in [third-party notices](../THIRD_PARTY_NOTICES.md). Rights to publicly redistribute the Wizards-derived playmats and other relevant material remain unresolved; no permission is implied by this review.
- Dependency audits identified a high-severity `@grpc/grpc-js` advisory in the root production dependency tree, through Firebase's Firestore package. The application has no direct Firestore imports, but the affected package is installed and its actual exposure must be assessed; Firestore currently pins an older gRPC range, so it was not overridden blindly. After a compatible lockfile update removed a high-severity `body-parser` advisory in Functions, eight moderate advisories remained in the Functions dependency tree. Reassess the current advisories and remediation before publication.
- A full browser run reported 68 passing, one skipped and 20 failing tests. Some outdated test assumptions were subsequently corrected and checked individually; the full suite has not yet been revalidated. An isolated Firebase integration run still failed while a participant remained in `reconnecting` after the host reloaded. Treat both as unresolved release blockers and rerun all required checks after addressing them.
- GitHub repository settings, production Firebase restrictions and an actual GitHub Actions release could not be verified without access to those services. The maintainer must complete the checks above before enabling publication.
